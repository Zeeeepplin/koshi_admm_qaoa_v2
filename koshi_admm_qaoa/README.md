# ADMM–QAOA transmission-reconfiguration case study

This directory contains the Eastern Nepal (Koshi/Kabeli) research code used by
`main_2.tex`. The test system is source-informed and combines reported,
planned, and hypothetical topology; nodal loads, most injections,
and some electrical parameters are engineering estimates rather than measured
SCADA/load-flow data.

Create the tested Python 3.12 environment from the repository root with:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-lock.txt
.venv/Scripts/python koshi_admm_qaoa/environment_report.py
```

On POSIX systems use `.venv/bin/python` instead. The environment report records
versions and non-identifying hardware/OS metadata in
`results/environment.json`.

## Notation and ordering contract

- `k` denotes a physical branch index; `ell` denotes a zero-based
  binary-vector position. `pi(ell)` maps a vector position to a physical
  branch.
- `alpha` is the continuous ADMM copy, `z` is the binary ADMM/QUBO copy,
  and `b` denotes a returned or measured bitstring. Arrays are stored in
  QuadraticProgram variable order unless explicitly marked as raw Qiskit
  display order.
- The minimized QUBO is `f_Q`; its global minimum is `f_Q_star` and its
  complete minimizer set is `Z_Q_star`. The Pauli mapping is
  `z_ell = (1 - Z_ell) / 2`, including the additive constant.
- `optimizer_run_exact_qubo_hit_fraction` uses independent optimizer runs as
  replications. Hardware counts instead report the distinct shot-level
  exact-set probability `p_shot_star`.

## Corrections made in the first-priority review pass

- The legacy `success` field is now reported as the **optimizer-run exact-QUBO
  hit fraction**. It is distinct from a shot-level probability assigned to the
  exact-QUBO minimizer set.
- Non-finite/disconnected SOC outcomes are represented by strict JSON `null`
  values plus explicit status flags; JavaScript-style `Infinity` is gone.
- QUBO component accounting is generated from the implementation. Cycle terms
  are nonzero at every benchmark size, and anti-islanding terms are nonzero
  from `n=8`; component counts overlap the dense cardinality component.
- The appendix now reports the saved disconnected results at `n=6,10,12` and
  marks SA physics as not recorded instead of copying losses from other methods.
- Numerical ADMM, QRAO-ablation, Qiskit `ADMMOptimizer`, and IBM-hardware claims
  are excluded from the frozen paper result set because their raw evidence was
  not released.

## Exact radiality correction

- `radiality.py` implements the exact single-commodity-flow spanning-tree MILP,
  exhaustive hard-radial QUBO enumeration, and the sorting/prefix solver for the
  linear-plus-uniform-cardinality special case.
- The historical QUBO remains available for provenance, but its pairwise cycle
  and anti-islanding terms are explicitly labelled heuristic. They do not
  enforce connectivity or radiality.
- Exhaustive auditing shows that the actual historical QUBO is nonuniform at
  every retained size, so the sorting baseline does not apply to it. The same
  baseline exactly matches enumeration when cycle and anti-islanding terms are
  set to zero.
- The old scaling protocol is hard-radial infeasible at `n=4,6,8`: forcing all
  non-decision switches closed creates a cyclic mandatory subgraph. At `n=10`
  and `n=12`, radial states exist, but no global historical-QUBO minimizer is
  radial.
- The former close-only connectivity repair has been replaced by a cycle-safe
  spanning-tree projection. It archives opened switches, closed switches,
  closed-edge count, component count, and cycle rank.

## Running a new benchmark

The full scientific environment requires CVXPY/CLARABEL and the Qiskit packages
imported by `solvers.py`. Run:

```bash
python benchmark.py
python artifact_pipeline.py --check
```

The updated benchmark retains every seed's returned bitstring and physics score,
including SA, and writes strict schema-v2 JSON incrementally.

The exact radiality audit itself requires no quantum or external hardware run;
it is regenerated by `artifact_pipeline.py`. A new method-to-method comparison
on a radial-feasible scaling design does require rerunning `benchmark.py` in the
full Qiskit/CVXPY environment. Its only authoritative destination is
`results/benchmark.json`; `artifact_pipeline.py` then updates
`generated/radiality_audit_table.tex`, `generated/coupling_table.tex`, the
benchmark figures, and the corresponding Results subsections in `main_2.tex`.
End-to-end ADMM outputs belong in `results/admm_runs.json` and may be cited only
in the manuscript's ADMM evidence-status subsection after regeneration.

## Predeclared post-contingency regeneration

The retained `results/benchmark.json` contains no forced-open branch and is a
base-case legacy artifact. It must not be described as post-contingency. The
separate specification `results/study_protocol.json` predeclares a hypothetical
N-1 outage of branch 3, Basantapur--Inaruwa circuit A. The faulted branch is
removed from the bit vector, leaving one full 13-variable decision space rather
than the invalid forced-closed size sweep.

Check the protocol and run the complete external workflow with:

```bash
python study_protocol.py --check
python benchmark.py --post-contingency
python run_post_contingency_sensitivity.py
python make_post_contingency_admm.py
python post_contingency_pipeline.py
python post_contingency_pipeline.py --check
```

The full run requires the documented Qiskit and CVXPY/CLARABEL environment.
Independent optimizer runs use process isolation because Qiskit's algorithm
RNG is process-global. The configured four-worker execution is used for the
independent quantum optimizer runs. QRAO's MagicRounding circuit evaluation
uses deterministic batches of 256, with the trial seed controlling basis
sampling and derived per-batch primitive seeds recorded in solver metadata.
Primary and
sensitivity runners checkpoint completed seeds and resume only
protocol-matching records.
Its authoritative inputs and outputs are deliberately separate from the legacy
artifact:

- `results/post_contingency_v1.json`: 30 independent QAOA/QRAO/SA trials using
  reproducible seed labels,
  exact QUBO reference, current-model physics, and raw objective gaps;
- `results/post_contingency_sensitivity_v1.json`: one-factor QUBO-weight and
  QAOA-iteration-budget sensitivity;
- `results/admm_post_contingency_v1.json`: complete residual histories, stopping
  reasons, rho sensitivity, configurations, and repair actions;
- `generated/post_contingency_results_table.tex`,
  `generated/post_contingency_validation_table.tex`,
  `generated/post_contingency_numbers.tex`, and
  `generated/post_contingency_admm_table.tex`;
- `figures/post_contingency_objective_gaps.png` and
  `results/post_contingency_manifest.json`.

The validation table reports raw connectivity/radiality, projection use,
fixed-topology SOC recovery, nonlinear-AC recovery, cone and angle residuals,
maximum voltage-bound and thermal-utilization excess, and validated loss with
explicit denominators.

The pipeline refuses to generate manuscript outputs unless all three result
artifacts are complete, use the frozen protocol hash, contain the predeclared
seeds, and include the required sensitivity and ADMM runs. The tables and figure
belong in a new Results subsection after `Hardware evidence status`; only then
may the abstract and conclusion be regenerated.

ADMM and hardware evidence are generated separately:

```bash
python make_admm_figure.py
python phase3_hardware.py --selftest
IBM_QUANTUM_TOKEN=... python phase3_hardware.py
```

`make_admm_figure.py` archives complete iteration histories in
`results/admm_runs.json`. Hardware now defaults to the same predeclared
branch-3 outage and 13-variable decision space as the prospective solver study.
Passing `--n-switches` explicitly is reserved for legacy diagnostics. A real hardware run
creates `results/hardware_YYYYMMDDTHHMMSSZ/` containing:

- authoritative `hardware_results.json` using schema `hardware-evidence-v2`;
- separate baseline and noise-management count files and job metadata;
- backend configuration, properties, target, and calibration timestamp;
- bound and transpiled QPY circuits plus a SHA-256 manifest;
- the exact-QUBO minimizer set, modal sample, best-energy sampled bitstring,
  sampled-objective mean with standard error, and shot-level exact-set
  probability;
- same-`n` physical validation of the modal sample, best-energy sample, and an
  exact-QUBO minimizer.

SamplerV2 measurement twirling plus dynamical decoupling is labelled a
noise-management condition, not TREX mitigation. Validate and create the
manuscript tables with:

```bash
python hardware_evidence.py results/hardware_<timestamp>
python hardware_evidence.py results/hardware_<timestamp> \
  --write-tex generated/hardware_evidence_tables.tex
```

The generated tables belong at the end of `main_2.tex` subsection
`Hardware evidence status`. Do not cite them until validation passes, and do not
infer a causal mitigation effect from only one job per condition.

Run the dependency-light and full local regression suite from the package
directory with:

```bash
python -m pytest -q
```

The tests are stored directly in `koshi_admm_qaoa/`; there is no nested
`tests/` directory.

## Important model limitations

- `continuous-model-v2` enforces fixed-power-factor shedding, explicit slack
  balances, branch-specific current/apparent-power ratings, and explicit
  off-nominal transformer taps. Tap positions remain assumed at 1.0 pu because
  source tap data have not yet been supplied.
- Final topologies now receive cone-tightness, voltage-drop, thermal, and angle
  diagnostics followed by a nonlinear fixed-injection AC power-flow recovery.
  This is a feasibility recovery check, not a nonlinear AC-OPF.
- The SOC numbers in the frozen migrated artifact were produced by the
  superseded continuous-model-v1. They are retained only for discrepancy tracing
  and must not be cited as results of the corrected model.
- The historical QUBO radiality and anti-islanding terms are heuristic quadratic
  surrogates; connectivity and radiality must be checked explicitly.
- No quantum advantage is claimed. The retained classical exact-QUBO timings are
  lower than the QAOA/QRAO timings at all tested sizes.
